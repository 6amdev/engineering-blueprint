# Blueprint = ตัวหลัก · สร้างโปรเจกต์ได้ไม่จำกัด

> เจ้าของ 2026-11-21: repo นี้เป็นตัวหลักของระบบทำงาน · แต่ละงานจริงสร้างจากตัวหลัก

## โครง
```
blueprint (repo นี้ · VERSION)          ← ปรับวิธีทำงาน / skill / แม่แบบ ที่นี่ที่เดียว
   ├─ node scripts/new-project.mjs ../งาน-a   → งาน-a (ครบในตัว · .blueprint.json บอกเวอร์ชัน)
   ├─ node scripts/new-project.mjs ../งาน-b   → งาน-b
   └─ …
```
- แต่ละโปรเจกต์ **อยู่ได้เอง**: กติกา skill แม่แบบ memory อยู่ใน folder ของมัน · ย้ายเครื่อง / เปลี่ยนชื่อได้ ไม่ต้องมีตัวหลักอยู่ด้วย
- `.blueprint.json` จดเวอร์ชัน + commit ของตัวหลักที่สร้างมา
- โปรเจกต์ไม่แก้ไฟล์กลาง (`AGENTS.md` §1–7 · `.claude/skills/` · `templates/`) ตรง ๆ · เจอจุดต้องปรับ → เสนอกลับเข้าตัวหลัก

## เปลี่ยนวิธีทำงาน
1. แก้ในตัวหลัก → ขึ้น `VERSION` (SemVer: กติกาเปลี่ยนจนของเดิมใช้ไม่ได้ = major · เพิ่ม skill/แม่แบบ = minor · แก้คำ = patch) → `CHANGELOG.md`
2. ดึงเข้าโปรเจกต์: `node scripts/upgrade-project.mjs <folder>` ดูรายการก่อน → ใส่ `--apply` → `git diff` → `npm install` → `npm run gate:test` → commit ในโปรเจกต์
   - ไฟล์ที่โปรเจกต์ไม่ได้แก้ = แทนที่ · แก้คนละจุด = รวมให้ · แก้จุดเดียวกัน = ไม่แตะ วางของใหม่ไว้ที่ `.blueprint-upgrade/` ให้รวมเอง
   - ไม่แตะ README · HANDOFF · stack-decisions · memory · หน้าคู่มือ `site/` · โค้ดของโปรเจกต์ · ไม่ commit ให้
   - ไฟล์ที่โปรเจกต์คัดลอกมาเองก่อนมีคำสั่งนี้: ระบุจุดเริ่มด้วย `--base <commit ของ blueprint>`

## บทเรียนจากโปรเจกต์ → ตัวหลัก
เสนอเป็น ADR ในตัวหลัก (`docs/decisions/`) · เขียนเป็นหลักการทั่วไปด้วยคำของตัวเอง · ลบทุกอย่างที่เฉพาะโปรเจกต์ / บริษัท / คนก่อน (ดู `CONTRIBUTING.md`)
