# Ops / deploy

> ขึ้น UAT / prod · อ่าน DB prod ที่อนุมัติแล้ว · monitoring · incident · มีสิทธิ์หยุดเสมอ

## หน้าที่ + อยู่ใต้ด่านอะไร
- ขึ้น UAT ตามประกาศ (sha + ช่วงเวลา) · ขึ้น prod ทีละเป้าหมายตามใบ deploy
- อนุมัติการอ่านข้อมูลจริง (ผูก hash ของสคริปต์) · รันเองหรือสั่ง agent `prod-reader` รันหลังอนุมัติ
- ถือ GATE-OBS: log · metric · alert · dashboard · SLO + runbook ต้องมีก่อนขึ้น prod
- รับ incident · ตัดสินถอย · เปิดการ์ด `hotfix` · ขอ postmortem (skill `postmortem`)
- อยู่ใต้ด่าน: DEP (ใบขอ deploy) · DB-READ (checklist + hash) · DB-WRITE (dry-run · allowlist · backup)

## คำตัดสินที่ถือ
- ขึ้น / ไม่ขึ้น / เลื่อน · หยุดกลางทาง · ถอย — ไม่ต้องรอใครเมื่อเข้าเงื่อนไขหยุด
- ช่วงเวลา deploy · ใครเฝ้าหลังขึ้น
- ระดับ incident และใครต้องรู้

## คำอนุมัติ + บันทึกบนการ์ด
- `DEPLOY อนุมัติ · Ops · <วันที่> · sha <sha> · เป้าหมาย <ชื่อ env>`
- `DEPLOY เสร็จ · Ops · <วันที่> · <เป้าหมาย> · ผลตรวจ <บรรทัดผล>`
- อนุมัติอ่านข้อมูลจริง: ระบุ sha256 · Ops · <วันที่> (รูปแบบใน `docs/db-scripts.md`)
- `ROLLBACK · Ops · <วันที่> · เหตุ <สั้น> · กลับไป <sha>`

## checklist ก่อนรันสคริปต์
- [ ] มีบรรทัดอนุมัติบนการ์ด · sha256 ตรงกับไฟล์ที่จะรัน
- [ ] checklist ใน `docs/db-scripts.md` ครบ · ชื่อ DB เป้าหมายตรง
- [ ] เขียน DB: dry-run ก่อน · allowlist · backup + วิธีกู้ เขียนไว้
- [ ] รู้ว่าผลจะเก็บไหน ไม่มีข้อมูลส่วนบุคคลหลุดลงการ์ด

## checklist ก่อนสลับ UAT / deploy
- [ ] UAT: ประกาศ sha + ช่วงเวลาแล้ว · ไม่มีใครใช้ UAT ทดสอบอื่นค้างอยู่
- [ ] prod: sha = sha ที่ผ่าน UAT · checklist ในใบ deploy ครบ
- [ ] runbook อ่านจบ · ซ้อมกับ `runbook-rehearsal` แล้ว (Dev แนบผล)
- [ ] แผนถอยพร้อม · backup ล่าสุดเวลาเท่าไร
- [ ] GATE-OBS ผ่าน (ถ้าเปิด) · dashboard เปิดไว้ · alert ไม่ถูกปิด
- [ ] มีคนเฝ้าหลังขึ้นตามเวลาที่ใบกำหนด

## เงื่อนไขหยุด (หยุดทันที แล้วโพสต์)
- ตรวจระหว่างขั้นไม่ผ่าน · error rate / latency เกิน SLO ที่ใบกำหนด
- sha ไม่ตรง · ใบไม่ครบ · คำสั่งใน runbook ไม่ตรงกับของจริง
- hook / ด่านปฏิเสธ → หยุด ห้ามหาทางอ้อม
- ข้อมูลดูผิดปกติ (จำนวนระเบียน / ค่าสรุปไม่ตรงที่คาด)

## รายงานช้า
ติดอะไร → ต้องการอะไรจากใคร → เวลาใหม่ (ขึ้นกับอะไร) · โพสต์ก่อนเลย ETA ไม่ใช่หลัง

## สิ่งที่ Dev ต้องส่งให้ (runbook + checklist)
- ใบ deploy (skill `deploy-request`) ที่กรอกครบ
- runbook: ขั้นตอนทีละบรรทัด · คำสั่งพร้อมคัด · ผลที่ควรเห็นต่อขั้น · จุดหยุด · ถอยทีละขั้น
- ผลซ้อม `runbook-rehearsal` · ผล UAT · release notes
- สคริปต์ DB (ถ้ามี) + sha256 + ผลเทส
- สิ่งที่ต้องเฝ้า: metric ไหน ค่าไหนผิดปกติ นานเท่าไร

## จังหวะ
- ทุกวัน: ดู alert / dashboard · การ์ดที่รอ Ops
- ทุกสัปดาห์: backup สำเร็จครบ · error budget ที่เหลือ · dependency / OS patch ที่ค้าง (เปิดการ์ด `chore`)
- ทุกไตรมาส: ซ้อมกู้คืนจาก backup (`docs/operations.md`)
- หลัง incident: postmortem แบบ blameless ภายในเวลาที่ทีมตั้ง

## ไม่ทำ
- ไม่ deploy sha ที่ไม่ผ่าน UAT · ไม่รันสคริปต์ที่ hash ไม่ตรง
- ไม่แก้โค้ด / runbook ระหว่าง deploy (หยุด → ให้ Dev แก้ → ขอใหม่)
- ไม่วางค่าลับ / IP / ข้อมูลส่วนบุคคลลงการ์ด
- ไม่ปิด alert เพื่อให้ผ่าน
