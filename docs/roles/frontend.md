# Frontend

> UI / UX · contract ฝั่งหน้าจอ · ตรวจหน้าจริงก่อนเรียกว่าเสร็จ
> สถานะ: v0.3.0 (2026-11-21)

## หน้าที่ + repo ที่ถือ
- หน้าจอ · component · ข้อความบนจอ (ร่าง → Owner อนุมัติ) · state ว่าง / โหลด / error
- ตรวจหน้าจริงบน UAT: 375px · desktop · ธีมสว่าง + มืด · ภาษาที่รองรับ
- ถือ GATE-UI และ GATE-A11Y ฝั่งคน เมื่อ UI เปลี่ยน (agent `qa-engineer` ลงมือ · Frontend ยืนยัน)
- กรอกต่อโปรเจกต์: repo / แอปฝั่งหน้าจอที่ถือ · design system / ไฟล์ดีไซน์อยู่ไหน

## คำตัดสินที่ถือ
- layout · interaction · component ที่ reuse · performance budget ของหน้า (เมื่อเปิด GATE-PERF)
- ถาม Owner: ข้อความถึงผู้ใช้ · flow ที่เปลี่ยนพฤติกรรมผู้ใช้ · สิ่งที่เก็บข้อมูลส่วนบุคคลบนหน้า

## รับงานจาก backend (contract)
- contract เขียนก่อนโค้ด: endpoint · request / response · error code · ตัวอย่างจริง (ข้อมูลปลอม)
- ใช้ schema เป็นแหล่งเดียว (เช่น OpenAPI / JSON Schema) · mock จาก schema เดียวกัน
- error ทุกตัวมีข้อความบนจอที่ Owner อนุมัติแล้ว
- เปลี่ยน contract = backward compatible หรือมี ADR + แผนเปลี่ยนทั้งสองฝั่ง
- เทส contract ทั้งสองฝั่ง ไม่ใช่ฝั่งเดียว

## ด่าน UI (checklist · เมื่อ UI เปลี่ยน)
- [ ] 375px ไม่มี scroll แนวนอน · ปุ่ม/จุดแตะ ≥ 24px (WCAG 2.2 AA) แนะนำ 44px
- [ ] ธีมสว่าง + มืด · สีตัวอักษรต่อพื้น ≥ 4.5:1
- [ ] WCAG 2.2 AA (เมื่อเปิด GATE-A11Y): ใช้คีย์บอร์ดได้ · focus เห็น · label / alt ครบ · ไม่สื่อด้วยสีอย่างเดียว
- [ ] state: ว่าง · โหลด · error · ไม่มีสิทธิ์ · ข้อมูลยาวผิดปกติ
- [ ] ข้อความตรงที่ Owner อนุมัติ · ภาษาไม่ตัดคำกลางคำ
- [ ] ไม่มีค่าลับ / key ใน bundle · ไม่ log ข้อมูลส่วนบุคคลใน console
- [ ] ภาพหน้าจอแนบการ์ด (มือถือ + desktop · ทั้งสองธีม)

## คำอนุมัติ + บันทึกบนการ์ด
`GATE-UI ผ่าน · Frontend · <วันที่> · UAT sha <sha> · ภาพ <ลิงก์>` · ไม่ผ่าน → ข้อ + ภาพ + วิธีทำซ้ำ

## deploy frontend
- ขึ้นพร้อมหรือหลัง backend ที่ contract ต้องใช้ · ไม่ขึ้นก่อน
- asset มี hash ในชื่อ · cache ยาว · HTML cache สั้น · ถอยได้ด้วยการสลับ build เดิม
- feature flag สำหรับหน้าที่ยังไม่พร้อมเปิด
- Ops เป็นคนขึ้น prod ตามใบ deploy เหมือนงานอื่น

## จังหวะ
- ทุกวัน: ตรวจหน้าจริงของการ์ดที่ขึ้น UAT
- ทุกสัปดาห์: ดูข้อร้องเรียน UI / a11y ที่ค้าง · component ซ้ำที่ควรรวม

## ไม่ทำ
- ไม่เรียกว่าเสร็จจาก dev server อย่างเดียว ต้องหน้าจริงบน UAT
- ไม่แต่งข้อความถึงผู้ใช้เองแล้วขึ้นเลย
- ไม่เปลี่ยน contract ฝ่ายเดียว
