# การโพสต์และการสื่อสาร

> ทุกคนทำงานผ่านการ์ด · โพสต์ต้องตอบได้ในรอบเดียว · การ์ด + git = audit trail
> สถานะ: v0.3.0 (2026-11-21)

## วิธีโพสต์ (ทุกโพสต์)
1. อ่านล่าสุดก่อน: `node scripts/board.mjs read <card>`
2. เขียนร่างลงไฟล์ (เช่น scratch / `drafts/` ที่ไม่ขึ้น git)
3. `node scripts/board.mjs post <card> <file>` → รัน `draft-check` + dry-run แสดงว่าจะส่งอะไรไปไหน
4. `draft-check` ผ่าน → เพิ่ม `--send` · ไม่ผ่าน → แก้ร่าง ห้ามหาทางอ้อม

## รูปโพสต์มาตรฐาน (แบบเดียวกับ `templates/card-post.md`)
```
[สถานะ] <รับ | ติด | เลื่อน | เสร็จ | ถาม> · <บทบาท> · <วันที่>
สรุป: 1–2 บรรทัด
ทางเลือก: ก) …  ข) …
แนะนำ: ก — เพราะ …
ที่มา: src/booking.ts:42@a1b2c3d · npm test → "12 passed"
ยังไม่ได้ตรวจ: …
ต่อไป: <ใครทำอะไร> · ETA <เวลา> (ขึ้นกับ …)
```
- ข้อเท็จจริงทุกข้อมีที่มา: `file:line@sha` · คำสั่ง + บรรทัดผล · log query + ช่วงเวลา
- ไม่มีทางเลือกให้ตัดสิน → ตัดบรรทัด ทางเลือก / แนะนำ ออกได้

## ถาม Owner (เฉพาะ: ธุรกิจ · เส้นทางเสี่ยงสูง R3 · ความปลอดภัย · ข้อความถึงผู้ใช้)
```
[ถาม] Owner · <วันที่>
คำถาม: จองห้องซ้อนเวลากันได้ไหม
ก) ไม่ได้ — ระบบปฏิเสธ
ข) ได้ ถ้าผู้จัดอนุมัติ
แนะนำ: ก — กฎง่าย ผู้ใช้เข้าใจ · เพิ่ม ข ทีหลังได้
บล็อก: story R-0012.S03 · ส่วนอื่นทำต่อได้
```
- 1–3 คำถามต่อโพสต์ · ตอบได้ด้วยการพิมพ์ ก / ข
- เรื่องที่ตัดสินเองได้ (ย้อนได้ · เพิ่มอย่างเดียว · ไม่เสี่ยง) ไม่ต้องถาม — ทำแล้วแจ้ง

## ความเงียบไม่ใช่การอนุมัติ
ยังไม่มีคำตอบบนการ์ด = ยังไม่ตัดสิน → ทำส่วนที่ไม่บล็อก แล้วทวงตามหัวข้อ "ทวง"

## คำอนุมัติ = audit trail
- ทุกคำอนุมัติเป็นความเห็นบนการ์ด: คำ · บทบาท · วันที่ · sha หรือลิงก์ของสิ่งที่อนุมัติ
- คำที่ใช้: `ACK` (brief / PRD / scope / change) · `go` (แบบ) · `GATES ผ่าน` · `UAT ผ่าน` · อนุมัติอ่านข้อมูลจริง (ระบุ sha256 · รูปแบบใน `docs/db-scripts.md`) · `DEPLOY อนุมัติ` · `DONE`
- **อนุมัติในแชต (เช่นจากมือถือ):** R1/R2 นับได้เมื่อ session หลักบันทึกบนการ์ดทันที: คำตอบ · "ตอบในแชต บันทึกโดย agent" · วันที่ · sha · R3 · ขึ้น prod · อ่านข้อมูลจริง ต้องให้ผู้อนุมัติยืนยันเองบนการ์ด · บันทึกแทนยืนยันตัวตนได้อ่อนกว่า
- ไฟล์เปลี่ยนหลังอนุมัติ = sha ใหม่ = ขอใหม่
- ตัวอย่างบรรทัดเต็ม: `docs/roles/owner-reviewer.md`

## คำต้องห้าม (ต่อโปรเจกต์)
- รายการอยู่ใน `blueprint.config.json` → `forbidden_words` (ไฟล์นี้ไม่ขึ้น git) · `draft-check` และ hook `pre-commit` บล็อก
- ใส่: ชื่อลูกค้า · ชื่อระบบภายใน · ชื่อคนที่ห้ามโผล่ในที่สาธารณะ
- กรอกต่อโปรเจกต์: รายการคำต้องห้าม

## ห้ามมีค่าลับ / IP / ข้อมูลส่วนบุคคล (PII)
- ห้าม: token · password · key · connection string · IP สาธารณะ · เบอร์ · อีเมลส่วนตัว · เลขบัตร · ข้อมูลลูกค้าจริง
- ผลสคริปต์ที่มีข้อมูลส่วนบุคคล → โพสต์แค่จำนวน / สรุป · ตัวจริงเก็บตามที่อนุมัติเท่านั้น
- `draft-check` ตรวจ: ค่าลับ · IP สาธารณะ · คำต้องห้ามใน config · commit hash เต็ม 40 ตัวที่ไม่มีใน repo · ลายเซ็นท้ายโพสต์ (ถ้าตั้งไว้)
- สิ่งที่เครื่องมือไม่ดูให้ เช่น ข้อมูลส่วนบุคคล รูปแบบ และความถูกต้องของเนื้อหา — ผู้โพสต์ตรวจเอง

## ETA + รายงานช้า
- ETA บอกเสมอว่าขึ้นกับอะไร: `ETA 16:00 (ขึ้นกับ UAT ว่าง)`
- จะเลย ETA → โพสต์ก่อนเลย: ติดอะไร → ขออะไรจากใคร → เวลาใหม่ (ขึ้นกับอะไร)

## ทวง
- อ่านความเห็นล่าสุดก่อนเสมอ (อาจตอบแล้ว)
- ทวงเมื่อเลย ETA หรือเลยเวลาตอบที่ทีมตกลง · ไม่ทวงถี่กว่านั้น (กรอกต่อโปรเจกต์: เวลาตอบต่อความเร่งด่วน · ความถี่ทวงสูงสุด)
- ทวงสั้น: ลิงก์คำถามเดิม · บล็อกอะไร · ต้องการอะไร
- เวลาทำงานตั้งใน `docs/roles/README.md` (กรอกต่อโปรเจกต์)

## สถานะ
| คำ | ใช้เมื่อ |
|---|---|
| รับ | เริ่มทำการ์ด / คำขอ · บอก ETA |
| ติด | ทำต่อไม่ได้ · บอกติดอะไร ขออะไร |
| เลื่อน | เปลี่ยน ETA · บอกเหตุ + เวลาใหม่ |
| เสร็จ | ครบตามที่รับ · ที่มา + ผลตรวจ |
| ถาม | ต้องการคำตัดสิน · รูปถาม Owner |

## บอร์ด (adapter ใน `blueprint.config.json` → `board.adapter`)
| adapter | การ์ดคือ | ความเห็น | ใช้เมื่อ |
|---|---|---|---|
| `local` (ค่าเริ่มต้น) | ไฟล์ `docs/cards/<id>.md` (เช่น `C-0001`) | ต่อท้ายไฟล์ พร้อมวันที่ + บทบาท | เริ่มใช้ · ทีมเล็ก · ไม่มีบริการภายนอก · ประวัติอยู่ใน git |
| `trello` | การ์ด Trello | comment ผ่าน API (key / token จาก env) | ทีมใช้ Trello อยู่แล้ว |
| `github` | Issue | comment ผ่าน `gh` CLI (`board.github.repo`) | โค้ดอยู่บน GitHub · อยากผูก PR |
| `none` | — | ไม่ส่ง | ไม่ใช้บอร์ด (post ถูกปฏิเสธ) |
- ค่าลับของบอร์ดอยู่ใน env เท่านั้น (ชื่อตัวแปรตั้งใน config) · ห้ามใส่ใน config หรือ URL
- `local`: แก้ความเห็นเก่าไม่ได้ · ผิดให้ต่อท้ายความเห็นแก้ · commit การ์ดพร้อมงาน
- กรอกต่อโปรเจกต์: adapter ที่ใช้ · รูปแบบ id การ์ด · ใครเปิดการ์ดได้
