# แผนที่คำถามก่อนเริ่มงาน

> ใช้กับ skill `intake` และ `grill` · เป้า: ก่อนเขียนโค้ด ทุกเรื่องมีคำตอบ ตั้งแต่ธุรกิจถึง tech stack ไม่มีช่องว่างให้ agent เดา
> **[ถาม]** = คนต้องตอบ · **[เสนอ]** = agent เสนอค่าแนะนำพร้อมเหตุผล คนรับหรือเปลี่ยน · หาคำตอบได้จาก repo = ไม่ถาม

## วิธีถาม (ครบ แต่ไม่ท่วม)
1. อ่าน repo ก่อน แล้วเติมทุกช่องที่ตอบได้เอง
2. ถามเป็นรอบตามหมวด A → H · รอบละ 1–3 ข้อ · ทุกข้อมีตัวเลือก + คำแนะนำ 1 ทาง + เหตุผล
3. ข้อ [เสนอ] รวมเป็นตารางเดียวต่อหมวด ตอบได้ว่า **"ตามแนะนำ"** หรือบอกเฉพาะบรรทัดที่เปลี่ยน
4. จบแต่ละหมวด ทวน 3 บรรทัด: เข้าใจว่า · ข้อสมมติ · ยังค้าง
5. **คนตอบไม่ได้หรือไม่แน่ใจ → ทำตัวอย่างให้เลือก** ไม่ถามซ้ำแบบเดิม: 2–3 ตัวอย่างที่เห็นภาพ + ข้อดี ข้อเสีย ราคา/แรงที่ใช้ ย้อนกลับยากแค่ไหน + คำแนะนำ 1 ตัว
   | ไม่แน่ใจเรื่อง | ตัวอย่างที่ทำให้ |
   |---|---|
   | กฎธุรกิจ | เหตุการณ์จริง 2–3 เรื่อง แล้วโชว์ผลของแต่ละกฎ |
   | flow / หน้าตา | ภาพร่างหรือหน้าจอนิ่ง (skill `ui-design`) |
   | tech stack | ชุดตัวอย่างใน `docs/stack.md` ปรับให้ตรงงานนี้ |
   | ข้อมูล / รายงาน | ตารางข้อมูลปลอม 5 แถว และรายงานที่ได้ |
   | ความเร็ว / ปริมาณ / ราคา | ตารางเทียบตัวเลข พร้อมที่มา หรือบอกว่าเป็นการประมาณ |
   | ยังเดาไม่ได้จริง ๆ | ของทดลองเล็ก ๆ ทิ้งได้ (แยก branch/โฟลเดอร์ ไม่ใช่โค้ดจริง) จำกัดเวลาและงบก่อนเริ่ม |
   เลือกแล้วเก็บตัวที่ไม่เลือกและเหตุผลไว้ใน ADR
5b. คำตอบใหม่ขัดของเดิม → ชี้ให้เห็นทันที ให้เลือก
6. ข้อที่ยังไม่มีคำตอบใส่ `❓` · ยังมี `❓` ใน brief หรือ `docs/stack-decisions.md` = `gate.mjs` ไม่รับ "go"
7. ตัดให้พอดีกับงาน: R1 ใช้หมวด A C H · R2 ทุกหมวดแบบสั้น · R3 ทุกข้อ · หมวด F ถามครั้งเดียวต่อโปรเจกต์ การ์ดต่อไปถามเฉพาะส่วนที่เปลี่ยน

## A. ธุรกิจและเป้าหมาย
- [ถาม] ปัญหาคืออะไร ใครเจ็บ ตอนนี้แก้ยังไง · สำเร็จวัดด้วยอะไร (ปัจจุบัน → เป้า)
- [ถาม] **ไม่ทำ** อะไร · รอบแรกเล็กสุดที่มีค่าคืออะไร
- [ถาม] กฎธุรกิจและข้อยกเว้น · ใครตัดสินเรื่องไหน · มีสิทธิ์ใช้ข้อมูล/เนื้อหา/ระบบนี้ไหม
- [ถาม] กำหนดเวลา · งบพัฒนา · งบรายเดือนหลังขึ้น

## B. ผู้ใช้และการใช้งาน
- [ถาม] มีผู้ใช้กี่กลุ่ม แต่ละกลุ่มทำอะไร เห็นอะไรได้ จำนวนคน · ช่วงใช้หนัก
- [ถาม] flow หลักทีละขั้น · เคสผิดปกติ: ว่าง ซ้ำ พร้อมกัน หมดเวลา ไม่มีสิทธิ์ เน็ตหลุด ลืมรหัส
- [เสนอ] อุปกรณ์ · เบราว์เซอร์ · ภาษา · เขตเวลา · รูปแบบวันที่/เงิน

## C. เกณฑ์ผ่าน
- [เสนอ → ถามยืนยัน] Given/When/Then ต่อ flow · ตัวอย่างข้อมูลจริงที่ปลอมแล้ว

## D. ข้อมูลและความปลอดภัย
- [ถาม] เก็บอะไร มาจากไหน ใครแก้ได้ · มีข้อมูลส่วนบุคคลไหม (วัตถุประสงค์ ระยะเก็บ การลบ/ส่งออก)
- [ถาม] ล็อกอินไหม แบบไหน · สิทธิ์ต่อบทบาท · ต้องมีประวัติการแก้ไหม
- [เสนอ] ระดับ R และ ASVS · สำรองข้อมูล (RPO/RTO) · ข้อมูลเดิมต้องย้ายเข้าไหม

## E. หน้าตาและประสบการณ์ (skill `ui-design`)
- [ถาม] มีแบรนด์ สี โลโก้ ตัวอักษร ตัวอย่างที่ชอบ/ไม่ชอบไหม · อยากให้รู้สึกแบบไหน 3 คำ
- [ถาม] เลือกจากภาพร่าง 2–3 แบบก่อนเขียนโค้ด
- [เสนอ] สว่าง/มืด · ความหนาแน่น · a11y (WCAG 2.2 AA) · ข้อความและน้ำเสียง

## F. Tech stack (ทุกส่วน · ลง `docs/stack-decisions.md`)
ทุกบรรทัดต้องเป็นอย่างใดอย่างหนึ่ง: เลือกแล้ว · ใช้ของเดิม · **ไม่ใช้ + เหตุผล** เกณฑ์เลือกอยู่ `docs/stack.md`
| กลุ่ม | บรรทัดที่ต้องตอบ |
|---|---|
| ก่อนเลือก [ถาม] | ทีมถนัดอะไร · ใครดูแลต่อ · มีของเดิม/ข้อบังคับองค์กรไหม · ต้องอยู่ในประเทศหรือในองค์กรไหม |
| หน้าเว็บ/แอป | ชนิด (เว็บ มือถือ เดสก์ท็อป CLI) · framework · ภาษา · styling/component · state · ฟอร์ม · i18n |
| หลังบ้าน | runtime + เวอร์ชัน · framework · รูปแบบ API + schema · งานเบื้องหลัง/ตั้งเวลา · realtime |
| ข้อมูล | ฐานข้อมูล · ORM/query · migration · cache · คิว · ไฟล์/รูป · ค้นหา |
| ตัวตน | วิธีล็อกอิน · session/token · สิทธิ์ · ที่เก็บค่าลับ |
| ต่อภายนอก | อีเมล/แจ้งเตือน · ชำระเงิน · แผนที่ · AI/โมเดล · ระบบอื่นในองค์กร |
| ที่รัน | โฮสต์/OS · container · โดเมน + TLS · dev / UAT / prod · ขยายยังไง |
| ส่งมอบ | git host · CI · วิธี deploy + ถอย · ที่เก็บ artifact |
| คุณภาพ | unit · integration · E2E/หน้าจอ · load · lint/format · coverage |
| ดูแล | log · metric · alert · ติดตาม error · สำรอง + ทดสอบกู้คืน |
| ข้อจำกัด | licence ที่รับได้ · dependency ที่ห้าม · ค่าใช้จ่ายรายเดือนสูงสุด |

## G. ขึ้นระบบและดูแล
- [ถาม] ใครอนุมัติขึ้น prod · ช่วงเวลาที่ห้ามขึ้น · ล่มได้นานแค่ไหน · ใครรับแจ้งนอกเวลา
- [เสนอ] SLO · หน้าต่างเฝ้า · แผนถอย · คู่มือ/อบรมใคร

## H. การทำงานร่วมกัน
- [ถาม] จุดอนุมัติตามระดับ R หรือมอบอำนาจอะไร · ตอบทางไหน (การ์ด/แชต) · งบต่อการ์ดและจำนวนรอบแก้ (`gate.mjs open`)
- [เสนอ] lane · R · ด่านเงื่อนไข · ขนาดงาน (XL = แตกก่อน)

## จบเมื่อ
ไม่มี `❓` · ไม่มีคำตอบขัดกัน · คนยืนยันสรุป 1 หน้า: ทำ/ไม่ทำ · เกณฑ์ผ่าน · หน้าตาที่เลือก · stack · งบ · ความเสี่ยง
