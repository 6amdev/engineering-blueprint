# uat — ทดสอบก่อนขึ้นจริง

> สถานะ: v0.3.0 (2026-11-21) · ขั้น 6 · กฎเต็ม: `docs/uat.md`

## เมื่อไหร่ใช้
หลังด่านขั้น 5 ที่ lane กำหนดผ่านที่ sha เดียวกัน · ทุก lane ที่มีโค้ดเปลี่ยน (hotfix ย่อช่วงเวลาได้ ไม่ข้าม smoke · chore อย่างน้อย smoke)

## input
- sha ที่จะขึ้น · test plan L2 จาก spec test inventory · เกณฑ์ผ่าน (G/W/T) · ด่านเงื่อนไขที่เปิด · ข้อมูลทดสอบ (สังเคราะห์ ไม่ใช่ข้อมูลจริง)

## ขั้นตอน
1. **ประกาศก่อนสลับ** บนการ์ด (ผ่าน skill `post`): sha · ช่วงเวลาใช้ UAT · ใครได้รับผลกระทบ · UAT ว่างไหม (ไม่ชนงานอื่น)
2. **ตรวจเครื่องปลายทางถูกตัว**: ชื่อ environment/host ตรงกับที่ประกาศ · ไม่ใช่ prod · ค่า config/ค่าลับเป็นชุด UAT
3. **ขึ้น sha** ตามขั้นตอน deploy ของ UAT · ตรวจ `sha` ที่รันอยู่จริงตรงกับที่ประกาศ · migration ผ่านและย้อนกลับได้
4. **L2** ตาม `templates/test-plan-l2-uat.md`: รันทีละเกณฑ์ผ่านผ่านระบบจริง (ไม่ mock) · บันทึกผล ผ่าน/ไม่ผ่าน + หลักฐาน (ภาพ/log + เวลา) · รวมเคสผิดปกติและสิทธิ์ต่างบทบาท
5. **ตรวจหน้าจริง** (เมื่อ UI เปลี่ยน): 375px และเดสก์ท็อป · ธีมสว่าง/มืด · สถานะ ว่าง/โหลด/error · ภาพหน้าจอไม่มีข้อมูลจริง (GATE-UI)
6. **ด่านเงื่อนไขบน UAT**: GATE-PERF (load/งบเวลา) · GATE-A11Y (WCAG 2.2 AA: คีย์บอร์ด · คอนทราสต์ · screen reader · เป้าแตะขั้นต่ำ 24px แนะนำ 44px) ตามที่เปิดไว้
7. **Audit vs scope**: เทียบสิ่งที่ทำกับ scope ที่ ack · ไม่ขาด ไม่เกิน
8. ไม่ผ่านข้อใด → ส่งกลับ implementer (กลับขั้น 4) แก้ที่ต้นเหตุ → ด่านใหม่ → ขึ้น UAT ใหม่ด้วย sha ใหม่ · ห้ามแก้ตรงบน UAT
9. **คืน UAT** ตามที่ประกาศ (คืนสถานะ/ข้อมูลทดสอบ) · โพสต์สรุปผล + ขอ owner-reviewer ยืนยันผ่าน UAT

## output
- ผลตาม `templates/test-plan-l2-uat.md` → `docs/test-plans/<card>-uat.md` · สรุปบนการ์ด · ภาพหน้าจอ

## agents
uat-release (ขึ้นและตรวจ sha) · qa-engineer (L2 + หน้าจริง · PERF · A11Y) · lead-reviewer (audit vs scope)

## gates
GATE-UI (ถ้า UI เปลี่ยน) · GATE-PERF/GATE-A11Y (ถ้าเปิด) · เกณฑ์ผ่านทุกข้อ · owner-reviewer ยืนยัน

## หยุดถาม owner เมื่อ
- เกณฑ์ผ่านกำกวมหรือต้องผ่อน · พบพฤติกรรมนอก spec ที่ผู้ใช้เห็น · ต้องใช้ข้อมูลจริง/PII ทดสอบ · UAT ชนกับงานอื่น
