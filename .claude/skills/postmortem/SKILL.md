# postmortem — สรุปเหตุแบบ blameless

## เมื่อไหร่ใช้
หลัง incident ที่ผู้ใช้เห็นผลหรือข้อมูลเสี่ยง · หลังทุก `hotfix` · หลัง near-miss ที่สำคัญ · เสร็จภายใน 5 วันทำการหลังเหตุสงบ (`docs/workflow.md`) · เป้าคือเรียนรู้ ไม่หาคนผิด (blameless): เขียนเรื่อง "ระบบ/กระบวนการ" ไม่ใช่ตัวบุคคล

## input
- timeline จริง (log · alert · คอมเมนต์การ์ด · commit) · ผู้ร่วมแก้เหตุ · ข้อมูลผลกระทบ · คำตัดสินใจระหว่างเหตุ

## ขั้นตอน
1. **เก็บหลักฐานก่อนเขียน**: log + ช่วงเวลา · metric · sha ที่ deploy · คอมเมนต์การ์ด · ไม่ใช้ความจำล้วน
2. **Timeline** ตามเวลาจริง (โซนเวลาเดียว): เริ่มเกิด · ตรวจพบ · ประกาศ · บรรเทา · แก้ · ปิด · คำนวณ **time to detect / time to mitigate / time to recover**
3. **ผลกระทบ**: ผู้ใช้/ฟังก์ชันที่กระทบ · ระยะเวลา · จำนวนโดยประมาณ · ข้อมูลเสียหรือรั่วไหม (ใช้ตัวเลข ไม่มี PII ไม่มีค่าลับ) · เทียบกับ SLO/error budget ถ้ามี
4. **ต้นเหตุ**: ถาม "ทำไม" ต่อเนื่อง (5 Whys) ถึงระดับกระบวนการ/ระบบ · แยก **ต้นเหตุ** กับ **ปัจจัยร่วม** · อะไรทำให้ไม่เจอก่อนขึ้น (ด่านไหนพลาด) · อะไรทำให้เจอช้า
5. **อะไรได้ผล / อะไรโชคช่วย** — ของที่ควรรักษาไว้
6. **Action items**: แต่ละข้อ = ลงมือทำได้จริง · ประเภท (ป้องกัน · ตรวจจับ · บรรเทา) · **เจ้าของ (role)** · **กำหนดวัน** · ผูกการ์ดใหม่ · เช่น เพิ่มเทสกันซ้ำ · เพิ่ม alert · ปรับด่านที่พลาด
7. **เรียนรู้ส่งกลับ**: หลักที่ใช้ได้ทั่วไป → ADR หรือข้อเสนอแก้ blueprint (เขียนเป็นหลักการ ไม่ใส่รายละเอียดโปรเจกต์จริง) · นำเข้า skill `retro`
8. ให้ owner-reviewer + ผู้ที่ร่วมเหตุอ่าน · แก้ข้อเท็จจริง · เผยแพร่ในทีมและเก็บถาวร

## output
- `templates/postmortem.md` → `docs/postmortems/<YYYY-MM-DD>-<slug>.md` · action items เป็นการ์ดใหม่ · อัป `docs/HANDOFF.md`

## agents
root-cause-analyst (ต้นเหตุ · timeline) · lead-reviewer (ตรวจเหตุผล) · tech-writer (เผยแพร่) · prod-reader เมื่อต้องอ่านข้อมูลจริง (หลังอนุมัติ)

## gates
ไม่มีด่านโค้ด · เกณฑ์: action items ทุกข้อมีเจ้าของ+วัน · ตรวจด้วยคนว่าไม่มี PII (draft-check ไม่ตรวจ PII) · โพสต์ผ่าน draft-check

## หยุดถาม owner เมื่อ (เฉพาะเรื่องที่ยังไม่ได้ตกลง · ที่ตกลงแล้วตัดสินเอง: `docs/workflow.md`)
- เหตุกระทบข้อมูลส่วนบุคคล (ต้องแจ้งผู้ใช้/หน่วยงานตามกฎหมาย) · ต้องแจ้งผู้ใช้ภายนอก (ข้อความ = owner อนุมัติ) · action ที่ต้องใช้งบ/ตัดสินใจเชิงธุรกิจ

## checklist done
- [ ] timeline มีหลักฐาน · ตัวเลขผลกระทบ · ไม่มีชื่อบุคคลเป็นต้นเหตุ
- [ ] ต้นเหตุระดับกระบวนการ + ปัจจัยร่วม
- [ ] action items มีเจ้าของ · วัน · การ์ด
- [ ] เผยแพร่แล้ว · บทเรียนทั่วไปส่งเข้า `retro`/ADR
