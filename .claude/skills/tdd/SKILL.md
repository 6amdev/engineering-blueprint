# tdd — เทสก่อนโค้ด

> สถานะ: v0.3.0 (2026-11-21) · ขั้น 4 · ศัพท์ (RED · oracle) อยู่ในอภิธานศัพท์ `docs/workflow.md`

## เมื่อไหร่ใช้
ทุกการเปลี่ยนพฤติกรรม รวม `bug` และ `hotfix` · refactor: เทสเดิมต้องผ่านทั้งก่อนและหลัง (ไม่มีเทสครอบ = เขียน characterization test ก่อน)

## input
spec + test inventory (`T-NNNN-NN`) · design brief ที่ได้ "go" (งานที่ต้องมี) · คำสั่งเทสใน `AGENTS.md` (`กรอกต่อโปรเจกต์:`)

## ขั้นตอน
1. **ฐานเทียบ**: branch สั้น · รันชุดเทสเต็มบน base เก็บรายชื่อเทสที่ล้มอยู่เดิม
2. **RED**: เขียนเทสทีละกลุ่มจาก test inventory ใส่รหัสในชื่อ · รันแล้วต้องไม่ผ่านเพราะพฤติกรรมที่ขาด/ผิด ไม่ใช่เพราะตั้งค่าผิด · เก็บหลักฐานเทสที่ไม่ผ่านก่อนแก้ (คำสั่ง + บรรทัดผล + sha)
3. เทสที่ดี: ตรวจพฤติกรรมที่มองเห็น · ล้มด้วยเหตุผลเดียว · ชื่อบอกเงื่อนไขกับผล · ไม่ขึ้นกับเวลา/ลำดับ/เครือข่ายจริง · มีเคสผิดปกติ
4. **GREEN**: โค้ดน้อยที่สุดที่ทำให้ผ่าน · ไม่เพิ่มสิ่งที่ spec ไม่ขอ
5. **REFACTOR**: ปรับโครงสร้างโดยเทสยังผ่าน · ตาม pattern ของ repo
6. โค้ดไม่ตรง spec = แก้โค้ด · เทสไม่ตรง spec = แก้เทสพร้อมเหตุผลบนการ์ดให้ reviewer เห็น
7. รันชุดเทสเต็มบน tip เทียบฐานข้อ 1 (มือหรือผล CI) — ไม่มีเทสล้มเพิ่ม
8. commit เล็กตาม Conventional Commits → skill `gate-check`

## output
เทส + โค้ด · แผนเทส + ผล L1 ใน `docs/test-plans/` · หลักฐานก่อน/หลังแก้ + ผลเทียบชุดเทสเต็มบนการ์ด

## agents
implementer (เขียน) · test-engineer (ตรวจอิสระ) · root-cause-analyst (lane bug/hotfix)

## gates
GATE-VERIFY · hotfix ก็ข้ามไม่ได้

## หยุดถาม owner เมื่อ
spec ไม่พอจะเขียนเทส · ผลที่ถูกเป็นเรื่องธุรกิจ · ต้องใช้ข้อมูลจริง/PII · ต้องเปลี่ยนเทสที่ผูกกับ AC ที่ ack แล้ว

## checklist done
- [ ] หลักฐานเทสที่ไม่ผ่านก่อนแก้ ครบทุกพฤติกรรมใหม่/บั๊ก
- [ ] เทสใหม่ผ่าน · refactor แล้วยังผ่าน
- [ ] เทสเดิมที่แก้มีเหตุผลจาก spec
- [ ] ชุดเทสเต็มไม่มีเทสล้มเพิ่มจาก base
