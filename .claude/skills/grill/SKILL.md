# grill — ไล่ถามให้สุดก่อนตัดสิน

> ขั้น 0–3 · ต่างจาก `challenger` ที่อ่านแล้วค้านคนเดียว: grill คุยกับคนทีละข้อ

## เมื่อไหร่ใช้
งานใหม่ที่ยังไม่ชัด · เอกสารมีคนเขียนมาแล้วแต่ยังไม่แน่ใจ · ก่อน "go" ของ R2/R3 · คนขอเอง

## input
เอกสารที่จะเจาะ (brief · spec · แบบ · ไฟล์ที่คนให้) · `docs/intake-map.md` · `docs/glossary.md` · ADR เดิม

## ขั้นตอน
1. อ่านเอกสารและ repo ก่อน · ทำรายการ: ข้อที่ขาด · ข้อที่ขัดกัน · คำที่ใช้ไม่ตรงกัน · ข้อสมมติที่ไม่มีที่มา · เรียงตามผลต่อแบบ
2. **ถามทีละ 1 ข้อ** เริ่มจากข้อที่ข้ออื่นขึ้นกับมัน · แต่ละข้อ: ทำไมสำคัญ · ตัวเลือก ก/ข · **คำแนะนำ + เหตุผล** · ตอบได้จากโค้ดหรือเอกสาร = ไปดูเอง ไม่ถาม
3. คนไม่แน่ใจ → ทำตัวอย่าง 2–3 แบบให้เลือก พร้อมข้อดี ข้อเสีย คำแนะนำ (ตารางใน `docs/intake-map.md`) · คำตอบกว้าง → ยกเหตุการณ์จริง 1 เรื่องให้ตัดสิน (เช่น "สองคนกดพร้อมกัน ใครได้")
4. ตอบแล้วแก้เอกสาร**ทันที** ไม่สะสม: ศัพท์ → `docs/glossary.md` (1 คำ 1 ความหมาย + คำที่ห้ามใช้แทน) · เรื่องย้อนยาก → ADR · ที่เหลือ → เอกสารนั้น
5. ขัดกับเอกสารหรือโค้ดเดิม → โชว์สองข้อความคู่กันพร้อมที่มา ให้คนเลือก
6. คนตอบว่า "ตามแนะนำที่เหลือ" ได้ → บันทึกทุกข้อเป็น "ข้อสมมติ (Owner รับตามแนะนำ)" ยกเว้น: ข้อมูลส่วนบุคคล · สิทธิ์ · เงิน · ย้อนไม่ได้ ต้องตอบเอง
7. หยุดเมื่อไม่มี `❓` ไม่มีข้อขัด และคำถามใหม่ไม่เปลี่ยนแบบแล้ว · สรุป 1 หน้าให้ยืนยัน

## output
เอกสารที่แก้แล้ว · `docs/glossary.md` · ADR · รายการข้อสมมติ · จำนวนข้อที่ถาม/ที่ตอบเอง

## agents

## gates

## หยุดถาม owner เมื่อ (เฉพาะเรื่องที่ยังไม่ได้ตกลง · ที่ตกลงแล้วตัดสินเอง: `docs/workflow.md`)
