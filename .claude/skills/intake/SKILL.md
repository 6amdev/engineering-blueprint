# intake — ทำความเข้าใจงานก่อนเริ่ม

> สถานะ: v0.3.0 (2026-11-21) · ขั้น 0 · ใช้ได้กับ agent ทุกเครื่องมือ

เป้า: ผู้ขอเริ่มด้วยคำขอสั้นได้ · agent เติมรายละเอียดด้วยการอ่านและถาม · ยังไม่ออกแบบหรือเขียนโค้ดจนกว่า brief ผ่าน DoR

## กติกาการถาม
- **อ่านก่อนถาม**: `AGENTS.md` · `docs/HANDOFF.md` · `docs/requirements/` · โค้ดที่เกี่ยว · หาคำตอบได้จาก repo = ไม่ถาม
- **ครั้งละ 1–3 ข้อ** เริ่มจากข้อที่มีผลต่อแบบมากที่สุด · แต่ละข้อมีตัวเลือก ก/ข/ค + **คำแนะนำ 1 ทาง + เหตุผล**
- ทวนความเข้าใจ 1 บรรทัดก่อนถามชุดถัดไป
- คำตอบที่วัดไม่ได้ ("เร็ว" "สวย" "ใช้ง่าย") → ขอตัวเลขหรือตัวอย่าง
- เรื่องธุรกิจ · เส้นทางเสี่ยงสูง · ความปลอดภัย · ข้อความถึงผู้ใช้ ต้องได้คำตอบจากผู้ตัดสิน · ความเงียบไม่ใช่การอนุมัติ
- ไม่ขอค่าลับ — ถามเพียง "เก็บที่ไหน ใครดูแล"

## หัวข้อที่ต้องครบ (ข้ามได้เมื่อ repo ตอบแล้ว)
1. **ปัญหา / เป้าหมาย** — เหตุผล · ตัวชี้วัดความสำเร็จ
2. **ผู้ใช้** — บทบาท/สิทธิ์ · อุปกรณ์ · ภาษา
3. **ขอบเขต** — ทำ · **ไม่ทำ** · รอบแรก vs รอบหลัง
4. **ขั้นตอนการใช้งาน** — flow หลัก · เคสผิดปกติ (ว่าง · ซ้ำ · หมดเวลา · ไม่มีสิทธิ์ · พร้อมกัน)
5. **ข้อมูล** — ชนิด · ที่มา · ระยะเก็บ · PII · ใครอ่าน/เขียน
6. **เกณฑ์ผ่าน** — Given/When/Then อย่างน้อย 1 ต่อ flow
7. **non-functional** — ความเร็ว · ปริมาณ · SLO · security · a11y · รูปแบบหน้าจอ
8. **ระบบรอบข้าง** — ต่อกับอะไร · เจ้าของ · contract
9. **ความเสี่ยง** — สิ่งที่ย้อนไม่ได้ · สวิตช์ปิด
10. **การปล่อย** — เป้าหมาย · ผู้ตรวจ · ผู้อนุมัติ · คู่มือ/ประกาศ
11. **กำหนดเวลา** — วันที่ · ขึ้นกับอะไร
12. **ผู้ตัดสิน** — เรื่องไหนใครตอบ (`docs/roles/`)
13. **สิทธิ์และความชอบด้วยกฎหมาย** — มีสิทธิ์ใช้ระบบ/ข้อมูล/เนื้อหานี้ไหม · ไม่ชัด = หยุดถาม Owner (หรือผู้ดูแลกฎหมายขององค์กร) · ไม่มีสิทธิ์หรือผิดกฎหมาย = ไม่รับ ปิดเป็น `rejected` พร้อมเหตุผล

## เลือก lane · ระดับ R · ด่านเงื่อนไข
บันทึกที่หัว brief และการ์ด · ไม่แน่ใจ = ถามผ่าน skill `post`

**1. lane**
| lane | ใช้เมื่อ | เส้นทาง |
|---|---|---|
| `feature` | ความสามารถใหม่ | ขั้น 0–9 |
| `change` | เปลี่ยนสิ่งที่ owner ack แล้ว | skill `change-request` → ย้อนไปขั้นแรกที่กระทบ → re-ack |
| `bug` | ระบบไม่ตรง spec | skill `bugfix` (ข้าม 1–3 ได้เมื่อ spec ไม่เปลี่ยน) |
| `hotfix` | production เสียหรือเสี่ยงเสียตอนนี้ | skill `hotfix` ตามขั้นที่ย่อได้/ห้ามข้ามใน `docs/workflow.md` แล้วทำ `postmortem` |
| `chore` | ดูแลระบบ: dependency · หนี้เทคนิค · refactor ไม่เปลี่ยนพฤติกรรม | build + ด่าน + smoke UAT + deploy · dependency เปิด GATE-DEPS |

**2. ระดับ R**: R1 ต่ำ ย้อนง่าย · R2 กลาง · R3 สูง = auth · ข้อมูลสำคัญทางธุรกิจ · ข้อมูลย้อนไม่ได้ · ข้อมูลส่วนบุคคล · security → R3 ต้องมีผู้อนุมัติคนที่สอง หรือในทีมคนเดียว owner บันทึกการรับความเสี่ยงบนการ์ด

**3. ด่านเงื่อนไข** (checklist เต็ม `docs/gates.md` · ไม่แน่ใจ = เปิด)
- [ ] **GATE-UI** — UI เปลี่ยน
- [ ] **GATE-A11Y** — มี UI ที่ผู้ใช้เห็นใหม่หรือเปลี่ยน (WCAG 2.2 AA)
- [ ] **GATE-PERF** — latency/ปริมาณ/query หนัก
- [ ] **GATE-PRIVACY** — ข้อมูลส่วนบุคคล
- [ ] **GATE-DEPS** — เพิ่ม/อัป dependency
- [ ] **GATE-OBS** — ขึ้น prod ครั้งแรก · service ใหม่ · เส้นทางสำคัญเปลี่ยน

พบเรื่องใหม่ระหว่างงาน = เปิดด่านเพิ่มบนการ์ดทันที
