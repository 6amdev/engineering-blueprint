# post — สื่อสารผ่านการ์ด

> สถานะ: v0.3.0 (2026-11-21) · กฎเต็ม: `docs/posting.md`

## เมื่อไหร่ใช้
ถามคำตัดสิน · ขออนุมัติ · รายงานผล · ประกาศ UAT · ตามงาน · ปิดงาน

## input
เรื่องที่จะสื่อ · การ์ด · คอมเมนต์ล่าสุด · หลักฐาน (`file:line@sha` · path + sha256 + ผล · log + ช่วงเวลา)

## ขั้นตอน
1. **อ่านล่าสุดก่อน**: `node scripts/board.mjs read <card>` · มีคำตอบแล้ว = ไม่ถามซ้ำ
2. **เลือกแม่แบบ**: `templates/card-post.md` หรือ `templates/owner-question.md` · เขียนเป็นไฟล์ร่าง
3. **คำถามที่ขอคำตัดสิน** มีครบ:
   - คำถาม 1 ประโยค (โพสต์ละ 1–3 เรื่อง)
   - ตัวเลือกพร้อมผลที่ตามมา ต้นทุน การย้อนกลับ
   - คำแนะนำ 1 ทาง + เหตุผล
   - สิ่งที่ถูกบล็อกระหว่างรอ
   - หลัก: ความเงียบไม่ใช่การอนุมัติ — รอคำตอบ และทำส่วนที่ไม่ถูกบล็อก
4. **รายงาน**: ข้อสรุป → หลักฐาน → ยังไม่ได้ตรวจ → ขั้นถัดไป
5. **ตามงาน**: ตามเวลาตอบที่ทีมตกลง (`docs/posting.md`) · บอกว่ารออะไรจากใคร
6. **ส่ง**: `node scripts/board.mjs post <card> <file>` (dry-run + draft-check) → แก้จนผ่าน → `--send`
7. **คำอนุมัติ** บันทึกเป็นคอมเมนต์: คำ · บทบาท · วันที่ · sha/ลิงก์

## output
คอมเมนต์บนการ์ดตาม adapter (`local` · `trello` · `github` · `none`)

## agents
ทุก agent ที่ร่างโพสต์ · intake-analyst (คำถาม) · status-reporter (รายงาน)

## gates
POST: `scripts/draft-check.mjs` ผ่าน · สคริปต์ตรวจเฉพาะค่าลับ · IP สาธารณะ · คำต้องห้ามใน config · commit hash 40 ตัวที่ไม่รู้จัก · ลายเซ็น (ถ้าตั้ง) และข้อความที่ถือว่าความเงียบเป็นการอนุมัติ · **ไม่ตรวจ** PII รูปแบบ หรือความถูกต้องของเนื้อหา — ผู้โพสต์ตรวจเอง

## หยุดถาม owner เมื่อ
เรื่องธุรกิจ · เส้นทางเสี่ยงสูง · ความปลอดภัย · ข้อความถึงผู้ใช้ · เรื่องย้อนได้และไม่เสี่ยง ตัดสินเองแล้วแจ้ง
