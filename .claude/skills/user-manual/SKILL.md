# user-manual — คู่มือผู้ใช้บน web doc

> สถานะ: v0.3.0 (2026-11-21) · ขั้น 8

## เมื่อไหร่ใช้
ฟีเจอร์/การเปลี่ยนแปลงที่ผู้ใช้เห็นเสร็จ และก่อนประกาศใช้ · ข้ามได้ถ้าผู้ใช้ไม่เห็นความต่าง (ระบุบนการ์ด) · อัปคู่มือเมื่อ `change`/`bug` เปลี่ยนสิ่งที่คู่มือเคยบอก

## input
- spec + stories (เพื่อรู้งานของผู้ใช้) · ผล UAT + ภาพหน้าจอ · release notes · ข้อความ UI จริง · ผู้อ่านเป้าหมาย (บทบาท · ระดับความรู้)

## ขั้นตอน
1. **จัดตาม Diátaxis** 4 ชนิด อย่าผสมในหน้าเดียว: **tutorial** (เรียนรู้ด้วยการทำตามจากศูนย์) · **how-to** (ทำงานหนึ่งอย่างให้สำเร็จ) · **reference** (ข้อมูลตรง ๆ: ค่า · สิทธิ์ · ข้อจำกัด) · **explanation** (ทำไม/แนวคิด)
2. **หนึ่งหน้า = หนึ่งงานของผู้ใช้** (task-based) ตั้งชื่อเป็นกริยา "จองห้องประชุม" ไม่ใช่ชื่อฟีเจอร์ · ใช้ `templates/user-manual-page.md`
3. **เนื้อหา how-to**: เป้าหมายหนึ่งประโยค · สิ่งที่ต้องมีก่อน · ขั้นตอนเป็นข้อ (1 ขั้น = 1 การกระทำ) · ผลที่ควรเห็น · ภาพจาก UAT (ไม่มีข้อมูลจริง/PII/ค่าลับ · มี alt text) · ข้อควรระวัง
4. **FAQ + แก้ปัญหาเบื้องต้น**: อาการ → สาเหตุ → วิธีแก้ · ใช้ข้อความ error ตามจริงของระบบ · บอกว่าติดต่อใครเมื่อแก้ไม่ได้
5. **ภาษา**: ไทยเป็นค่าเริ่มต้นใน `site/` · อังกฤษใน `site/en/` (ชื่อไฟล์เดียวกัน = คู่แปล) · ใช้คำเดียวกับที่ปรากฏบนหน้าจอ · ประโยคสั้น · เสียง active
6. **การเข้าถึง**: หัวข้อเรียงระดับ · ลิงก์มีความหมาย · ภาพมี alt · ตารางมีหัวคอลัมน์
7. **โครงเว็บ**: เพิ่มหน้าใน sidebar ของ `site/.vitepress/config` ทั้งไทยและ `/en/` · ลิงก์ข้ามหน้า · ลิงก์ไป release notes
8. **ตรวจ**: `npm run docs:build` ผ่าน (ไม่มีลิงก์เสีย) · `npm run docs:dev` ดูที่ **375px** ทั้ง 2 ภาษา · ให้คนอื่น/qa-engineer ลองทำตามขั้นตอนบน UAT ได้จริง
9. ข้อความที่ผู้ใช้อ่าน = **owner อนุมัติ** ก่อนเผยแพร่ · เผยแพร่พร้อม release

## output
- หน้า markdown ใน `site/` (th) และ `site/en/` · ภาพใน `site/public/` · sidebar อัป · อัป HANDOFF

## agents
tech-writer (หลัก) · qa-engineer (ลองทำตามคู่มือบน UAT)

## gates
`npm run docs:build` ผ่าน · DoD: คู่มืออัปเมื่อผู้ใช้เห็นความต่าง · GATE-A11Y ถ้าเปิด (กับเว็บคู่มือด้วย)

## หยุดถาม owner เมื่อ
- ข้อความ/ศัพท์ที่ผู้ใช้เห็น · ระดับรายละเอียดที่เปิดเผย (เช่น ขั้นตอนที่เกี่ยวกับความปลอดภัย) · ภาพที่อาจมีข้อมูลจริง
