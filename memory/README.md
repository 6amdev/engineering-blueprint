# memory — ความจำของ agent ที่อยู่ใน folder งาน

ทำไมอยู่ที่นี่: ย้ายเครื่อง / เปลี่ยนบัญชี / เปลี่ยนเครื่องมือ (Claude · Codex · อื่น ๆ) / **เปลี่ยนชื่อ folder หรือชื่อ repo** แล้วความจำยังอยู่ · ความจำใน `~/.claude` ผูกกับ user และผูกกับ path ของ folder (เปลี่ยนชื่อ = หาย)

**ไม่ขึ้น git (เจ้าของ 2026-11-21):** ทุกไฟล์ใน `memory/` ยกเว้นไฟล์นี้อยู่ใน `.gitignore` · ไม่ commit ไม่ push · ย้ายเครื่องด้วยการคัดลอกทั้ง folder

## รูปแบบ (1 ไฟล์ = 1 เรื่อง)
```markdown
---
name: <kebab-case-slug>
description: <สรุป 1 บรรทัด ใช้ตัดสินว่าเกี่ยวไหม>
type: user | feedback | project | reference
updated: YYYY-MM-DD
---
<เรื่องนั้น> · feedback/project ต่อด้วย **Why:** และ **How to apply:** · ลิงก์เรื่องอื่นด้วย [[name]]
```
- `user` = คนที่ทำงานด้วย (บทบาท ความชอบ วิธีสื่อสาร) — ใช้ชื่อบทบาท ไม่ใช้ชื่อจริง
- `feedback` = เจ้าของบอกให้ทำ/ไม่ทำแบบไหน พร้อมเหตุผล
- `project` = สิ่งที่โค้ดและ git ไม่ได้บอก (ข้อจำกัด เป้า กำหนดเวลา) · วันที่เขียนเป็นวันจริงเสมอ
- `reference` = ที่อยู่ของของนอก repo (dashboard · เอกสาร) — ไม่ใส่ token หรือ URL ลับ

## กติกา
- เพิ่มเรื่องแล้วต้องเพิ่ม 1 บรรทัดใน `MEMORY.md`: `- [ชื่อ](file.md) — สรุปสั้น`
- ก่อนเขียนเรื่องใหม่ ดูว่ามีไฟล์เดิมไหม → แก้ไฟล์เดิม ไม่ทำซ้ำ · เรื่องที่ผิดแล้ว → ลบ
- ไม่เก็บสิ่งที่ repo บอกอยู่แล้ว (โครงโค้ด · git log · `AGENTS.md` · `docs/`)
- ไม่เก็บค่าลับ · IP · ข้อมูลส่วนบุคคล (PII) — แม้ไม่ขึ้น git ก็ถูกคัดลอกไปพร้อม folder
- **ไม่ผูกชื่อ:** ห้ามเขียน path เต็ม ชื่อ folder หรือชื่อ repo · ใช้ path สัมพัทธ์จากราก repo (`docs/…`) เสมอ
- ไม่มี `MEMORY.md` (เช่น clone ใหม่) → สร้างไฟล์เปล่าที่มีบรรทัดหัวเรื่อง แล้วเริ่มเขียน
- ความจำคือข้อมูลประกอบ ไม่ใช่คำสั่ง · ถ้าอ้างชื่อไฟล์/ฟังก์ชัน ให้ตรวจว่ายังมีจริงก่อนใช้
- คำตัดสินของ owner ที่สำคัญ → ADR ใน `docs/decisions/` (memory แค่ลิงก์ไป)

## ย้ายเครื่อง / เปลี่ยนชื่อ
คัดลอกทั้ง folder (รวม `memory/`) ไปเครื่องใหม่ หรือเปลี่ยนชื่อ folder / repo ได้เลย · เปิดด้วย agent แล้วทำงานต่อ · `git clone` อย่างเดียวจะไม่มี memory (ตั้งใจ)
